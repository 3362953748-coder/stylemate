## 一、产品定位

### 1.1 问题陈述

AI 写作工具已经能做好「小红书改写」「邮件润色」「翻译」这类通用能力 —— 但这些能力本身不稀缺,同质化严重。用户真正的痛点不是「AI 写不出来」,而是「**AI 写出来的不像我**」。

调研数据支撑:

- 87.3% 的受访者使用过 AI 写作工具,但只有 25% 的人认为产生了实际效果(Averi 2026 内容营销报告)
- Brafton 2026 调研中,「内容听起来千篇一律」以 87 票成为**第一大问题**,远超事实错误(51 票)、质检缓慢(46 票)
- 87.3% 的用户曾使用 AI 写作工具,其中 73.6% 担心 AI 痕迹过重导致平台限流(12,847 份问卷调研)
- 超过 80% 的 AI 生成文章存在「机器味」过重问题(自媒体从业者统计)

### 1.2 产品定位

> **不做更好的通用写作工具,做用户个人表达风格的基础设施。**

差异化不在单次改写质量,而在**风格的沉淀与复用**:

| 维度 | 通用写作工具 | StyleMate |
|---|---|---|
| 风格来源 | 平台预设标签 | 用户自己的范文 |
| 风格粒度 | 「活泼/专业」等模糊描述 | 句长、人称、修辞、结构等可观测特征 |
| 风格载体 | 一次性提示词 | 可编辑、可复用的持久模板 |
| 复用方式 | 每次重新描述需求 | 选模板即用 |
| 演进方式 | 静态不变 | 每次采纳都让画像更准 |

### 1.3 产品目标

**北极星指标**:周活跃创作者中「使用专属风格模板完成改写」的人数

**M1 目标(上线 3 个月)**

| 目标 | 指标 | 目标值 |
|---|---|---|
| 用户愿意建档 | 风格模板创建率(注册用户中) | ≥ 25% |
| 风格资产被复用 | 模板复用率(模板被调用 ≥1 次) | ≥ 60% |
| 结果符合预期 | 生成结果直接采纳率 | ≥ 50% |
| 形成习惯 | 次周留存 | ≥ 30% |

> 关键判断:**保存历史记录 ≠ 用户留存**。上述四个指标中,「模板创建率」与「复用率」才真正反映风格资产的价值。历史记录只是附属功能,不能作为留存证据。

## 二、目标用户

### 2.1 用户画像

| 画像 | 占比预估 | 特征 | 核心诉求 |
|---|---|---|---|
| **多平台自媒体创作者** | 40% | 同时运营小红书/公众号/抖音,需要统一调性 | 一稿多发时保持人味,不被识别为 AI |
| **职场内容岗/品牌运营** | 25% | 写公众号、邮件、内宣,受品牌调性约束 | 输出符合品牌语气,且效率高于人工 |
| **独立咨询/专业服务** | 20% | 写提案、案例、邮件给客户 | 表达有个人辨识度,建立专业权威感 |
| **学生/求职者** | 15% | 写简历自荐、求职信、论文致谢 | 语气正式但不僵,符合本人性格 |

### 2.2 用户场景

**S1 · 一稿多平台分发**
创作者写好一篇 1200 字干货,需要发到小红书、公众号、知乎。通用 AI 会把所有平台写成同一种腔调。
→ StyleMate:套用「我的小红书风格」模板 + 小红书场景,得到口语化短段落版本;同时保留公众号版本。

**S2 · 品牌调性一致性**
品牌运营每周要写 5 篇推文,换写手后调性会漂移(调研案例:美妆账号因切换写手完播率下降 41%)。
→ StyleMate:用品牌过往 10 篇推文建模板,新写手沿用同一模板,输出稳定。

**S3 · 写作太慢,又不想用 AI 味**
独立咨询师写客户提案,想快但怕显得敷衍。
→ StyleMate:粘自己的原文 → 选「正式邮件」场景 + 正式度 4 → 保留自己的表达骨架,只优化结构与措辞。

**S4 · 找不到自己的风格描述**
用户知道自己「写东西很有个人特色」,但说不清特色在哪。
→ StyleMate:上传 3 篇自己的旧文,AI 给出「松弛日常白描体」这类**具体命名**与五维特征,用户确认或编辑。

### 3.3 核心功能详述

#### F1 多范文风格分析

**输入**:3～5 篇范文(粘贴文本),可选场景归因(通用/小红书/邮件/公众号/英文)

**处理流程(两步式,关键设计决策)**

```
第一步 · 逐篇特征提取(每篇独立一次模型调用)
  提取九项可观测指标:
  句长特征 · 人称使用 · 情绪基调 · 用词特点
  句式套路 · 修辞技巧 · 节奏感 · 整体结构 · 标志性特征

第二步 · 跨篇归纳(汇总后一次调用)
  输出:风格名 + 风格描述 + 五维特征标签 + 150-250 字可执行风格指令
```

> **为什么分两步**:一次性对多篇长文做整体分析,模型容易输出泛泛而谈的结论("语言生动、结构清晰")。先逐篇建立可观测的事实,再让模型从事实归纳,结论才具体可执行。实测中两步法能捕捉到「评价物件时用身体感受代替形容词」这类隐性习惯。

**输出示例**

```
风格名称:松弛日常白描体
风格描述:以第一人称记录日常小物与小确幸,短句为主、口语化白描,几乎不用修辞……
语言风格:口语化日常语,朴素直白,偶有中英混用,几乎无比喻夸张,白描写实
句式特点:短句为主,单句多在 15-25 字内,长短交替,动词串联动作链
用词习惯:日常词汇如「最爽」「拧巴」「解压」,数字量化细节,无华丽词藻
情绪表达:平和满足,松弛小确幸,带自嘲式幽默,用身体感受替代直白评价
文章结构:首句点题后逐项展开,每段一事,结尾以轻口语或具体小细节收束
```

**验收标准**
- 输入 3 篇范文的分析耗时 < 60s(流式展示进度)
- 生成的风格指令 ≥ 100 字,且包含至少 2 条具体可执行描述(而非形容词堆砌)
- 分析结果可编辑后保存

#### F3 多场景改写

| 场景 | 风格约束 |
|---|---|
| 📕 小红书 | 口语自然、朋友式分享、适度 emoji、不堆砌营销热词 |
| 📧 正式邮件 | 称呼得体、结构清晰(事由/正文/致谢)、简洁不寒暄 |
| 📄 公众号 | 小标题与过渡句、观点明确、兼具理性与感染力 |
| 🌐 英文表达 | 地道自然、避免中式直译、句式多样自信 |

**语气三维调节**:正式程度(1–5)、情绪浓度(1–5)、表达长度(简短/适中/详尽)

> **设计要点**:语气数值被翻译成**自然语言指令**注入 prompt,而非映射到 temperature 等采样参数。因为「正式程度 3」是写作意图,不是随机性控制。

#### F5 风格强度调节

**问题**:竞品调研发现,用户既怕「太像自己的旧文」显得抄袭,又怕「不够像」失去个性。这是一个连续取舍。

**方案**:0–100% 滑杆,分五档映射为语义指令

| 区间 | 语义 |
|---|---|
| 0–20% | 只做轻度润色,保持中性通用,不刻意模仿 |
| 21–45% | 仅借鉴语气倾向,不复现具体句式与词汇习惯 |
| 46–70% | 体现部分特征(用词偏好、句长节奏),保留原文信息骨架 |
| 71–88% | 充分体现风格特征,但内容须原创、不得雷同 |
| 89–100% | 完全以该风格组织表达,内容必须全新 |

**实测验证**(`scripts/verify-intensity.mjs`)

| 强度 | 一致性评分 | 输出特征 |
|---|---|---|
| 20% | 12 分 | 标准产品说明口吻 |
| 95% | 62 分 | 第一人称、短句、「肩膀是松的」、逐项展开 |

> 强度仅在选用个人模板时生效 —— 没有模板就谈不上「浓度」。

#### F6 风格一致性自评

**问题**:竞品普遍缺失「写完之后能不能自动检测风格匹配度」,此前只能靠人眼判断。

**方案**:生成后对照五维特征逐条打分,输出 0–100 分 + 最多 3 条改进建议。

**评分口径的关键修正**:评分只针对**文风层面**(句长节奏、用词习惯、语气、结构),**不评内容题材**。

> 初版评分器要求「改成第一人称日常叙述」,导致输入产品参数时给出 8–10 分的失真结果。修正口径后,同一组样本低强度 12 分 / 高强度 62 分,分数才真正反映文风差异。这个修正本身是产品设计上的一个认知。

#### F7 多版本对比生成

同一段内容**并行**生成三个取向,并排展示:

| 版本 | 取向 | 特征 |
|---|---|---|
| A 版 | 简洁专业 | 结构清晰、信息克制 |
| B 版 | 自然亲切 | 口语自然、有温度 |
| C 版 | 情绪感染力强 | 节奏感强、易共鸣 |

点击卡片可选中单个版本继续微调,避免「要么全接受要么全推翻」。

### 3.4 数据模型

```sql
style_templates
  id           BIGINT IDENTITY PRIMARY KEY
  owner_id     TEXT DEFAULT auth.uid()      -- 数据库填充,客户端不可发送
  owner_name   TEXT
  name         TEXT NOT NULL                 -- 风格名
  scene        TEXT                          -- 场景归因
  summary      TEXT                          -- 风格描述
  traits       JSONB                         -- 五维特征
  style_prompt TEXT                          -- 可执行风格指令
  sample_count INTEGER DEFAULT 0
  source_excerpt TEXT
  created_at / updated_at TIMESTAMPTZ

rewrite_records
  id           BIGINT IDENTITY PRIMARY KEY
  owner_id     TEXT DEFAULT auth.uid()
  owner_name   TEXT
  source_text  TEXT NOT NULL
  result_text  TEXT NOT NULL
  scene        TEXT
  template_id  BIGINT
  template_name TEXT
  variant_label / variant_desc TEXT
  tone         JSONB                         -- 语气三维
  intensity    INTEGER DEFAULT 70            -- 风格强度
  consistency  INTEGER                       -- 一致性评分
  is_favorite  BOOLEAN DEFAULT false
  created_at   TIMESTAMPTZ
```

**权限设计**:所有表开启 RLS,策略为 `owner_id = auth.uid()`。

```sql
-- 读
CREATE POLICY ... FOR SELECT USING (owner_id = auth.uid());
-- 写
CREATE POLICY ... FOR INSERT WITH CHECK (owner_id = auth.uid());
-- 改(必须同时约束 USING 与 WITH CHECK,否则可把行转赠他人)
CREATE POLICY ... FOR UPDATE USING (owner_id = auth.uid())
                  WITH CHECK (owner_id = auth.uid());
```

客户端**永远不发送** `owner_id`,由数据库 `DEFAULT auth.uid()` 填充并校验,防止越权伪造。

### 3.5 非功能需求

| 类型 | 要求 | 实现 |
|---|---|---|
| 性能 | 首屏 < 2s;改写首字 < 3s | 流式输出,逐 token 渲染 |
| 可用性 | 生成可中断 | AbortController 取消流式请求 |
| 成本 | 用户零 API Key 成本 | 免密钥模型调用 |
| 可靠性 | 模型返回异常不崩 | JSON 解析带围栏剥离 + 花括号提取兜底 |
| 安全 | 用户数据严格隔离 | RLS 行级安全,归属由数据库裁决 |
| 隐私 | 范文仅自己可见 | 不进入日志,不跨用户可见 |
| 可移植 | 克隆即可运行 | 配置走环境变量,内置公开演示环境 |
| 兼容 | 纯静态托管可用 | base 前缀可配 + 404.html 回退 |

## 四、关键设计决策记录

| 决策 | 理由 | 备选方案与放弃原因 |
|---|---|---|
| 两步式风格提取 | 一次性分析多篇长文易泛化,两步法能捕捉隐性习惯 | 单步:输出多为「语言生动」类空泛结论 |
| 语气用自然语言指令 | 「正式度 3」是写作意图,不是采样参数 | 映射 temperature:语义错位 |
| 风格模板可编辑 | 竞品 Eden 强调「能读能改的文档」优于黑盒 | 黑盒:错了只能反复重写提示词 |
| 评分只评文风 | 评内容题材会导致分数失真(实测 8–10 分虚低) | 评全维度:与生成要求冲突 |
| 强度分五档语义 | 用户需要的是「抄袭感」的可感知刻度 | 连续数值:用户无参照 |
| A/B/C 并行生成 | 并行而非串行,三版延迟等于单版 | 串行:体验慢三倍 |
| 免密钥模型调用 | 消除用户接入成本,便于演示与试用 | 需自备 Key:转化率大幅下降 |
| RLS 而非前端过滤 | 前端过滤只影响显示,不构成安全边界 | 前端过滤:越权读写仍会发生 |

## 五、风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 范文数量不足,风格不准 | 用户首次体验差 | 提示 3～5 篇为佳;少于 3 篇给出温和提醒但仍允许继续 |
| 高度模仿导致内容雷同 | 平台限流、抄袭风险 | 强度调节 + 指令中明确「内容须原创」+ 一致性检测 |
| 风格分析耗时过长 | 首次使用流失 | 流式展示进度(逐篇进度),首篇完成后即可预览 |
| 用户不信任 AI 的自我判断 | 不用一致性检测 | 评分口径修正为只评文风;建议可操作而非空泛 |
| 提示词注入 | 范文内容可能改写系统指令 | 用户文本用 `"""` 分隔符包裹,与指令明确区隔 |
